# 중앙대학교 도메인 신청 준비 — Trauma Stress Lab

정보통신처 「온라인 신청 안내 매뉴얼(웹호스팅·도메인)」 기준으로, 이 저장소(`caupsynr`)가
운영 중인 홈페이지에 맞춰 정리한 신청 준비 문서.

---

## 0. 핵심 결론

> **2026-10-06 정보인프라팀 회신 반영.** 상세는
> [`domain-request-email.md`](./domain-request-email.md) 1장.

1. **도메인은 `psynr.cau.ac.kr`을 계속 쓴다. 다만 절차는 "중지 → 신규 신청" 두 단계다.**
   레코드 수정이 아니라, 교수님이 기존 도메인 사용 중지 메일을 직접 보내고 종합정보시스템에서
   신규 도메인 신청을 하는 방식이다. 현재 레코드는 종료된
   Wix(`td-ccm-neg-87-45.wixdns.net`)를 가리켜 404를 반환하므로 중지 자체에는 손해가 없다.
2. **중앙대 SSL 인증서 설치가 학교 기준이다.** Render는 인증서 직접 설치를 지원하지 않고
   Let's Encrypt·Google Trust Services 자동 발급만 제공한다. 자동 발급 인증서로 갈음
   가능한지 회신 메일로 묻는다. 불가하면 인증서를 설치할 수 있는 환경으로 옮겨야 한다.
3. **교내 웹호스팅 신청은 필요 없다.** 교내 호스팅은 ASP/PHP만 지원하고 이 사이트는 Flask다.
4. **신청 주체는 교수님이다.** 매뉴얼 3p 서비스 대상이 "교원, 직원"이고, 회신에서도
   교수님 직접 신청으로 확인됐다.
5. **첨부 점검표 2종이 모두 해당된다.** 양식은 도메인 신청 페이지에서 받는다(회신 확인).
   점검표가 묻는 코드 보완 8건은 반영 완료(§4).

## 1. 신청 절차 (매뉴얼 → 우리 상황)

신청서 위치: **종합정보시스템 > 행정 > 정보통신처 > 신청서 관리**

| 매뉴얼 단계 | 우리 경우 |
|---|---|
| 웹호스팅 신청 | **해당 없음** — 교내 호스팅은 ASP/PHP만 지원, 우리는 Flask |
| 원격접속 계정(ARCON/VPN) 신청 | 해당 없음 — 교내 호스팅 서버 FTP 접속용 |
| 보안정책 등록 신청 | 해당 없음 — 교내(연구실) 서버가 아니라 외부 클라우드. 단, 향후 연구실 PC/서버로 옮기면 필수 |
| **도메인 신청** | **해당** — 아래 §2 값으로 작성 |

도메인 신청 화면 순서: ① 추가 → ② 사용자 정보 입력 → ③ 웹사이트명·도메인명 입력 →
④ 홈페이지 취약점 점검표 첨부(필수) → ⑤ 개인정보처리시스템 안전성 확보조치 관리실태
점검표 첨부(로그인 있으므로 해당) → ⑥ 개인정보 수집 동의 → ⑦ 저장 → ⑧ 승인요청

## 4. 점검표 대응 현황 (코드 근거)

### 이미 충족

| 항목 | 근거 |
|---|---|
| CSRF 방어 | `app.py:42` `CSRFProtect(app)` 전역 적용 |
| 비밀번호 안전 저장 | `app.py:593` `generate_password_hash(..., method='pbkdf2:sha256')` |
| 로그인 무차별 대입 완화 | `app.py:1228` `@limiter.limit("10 per minute", methods=["POST"])` |
| SQL 인젝션 | 전 쿼리 파라미터 바인딩(`?`), 문자열 보간은 내부 테이블명에만 사용 |
| 업로드 제한 | 확장자 화이트리스트(`app.py:54`), `secure_filename`, `MAX_CONTENT_LENGTH` 50MB |
| 접근통제 | `@login_required` + `_require_project_owner()` 프로젝트 소유권 검사 |
| 감사 기록 | `app.py:392` `audit()` — 행위/대상/전후값 기록 |
| 개인정보 최소수집 | 연구 참여자는 코드·성별·나이만 저장(가명처리), 이름·연락처 미저장 |
| 디버그 모드 | `app.py:3759` `app.run(debug=False)` |

### 신청 전 보완 — 처리 완료

| 항목 | 조치 | 근거 |
|---|---|---|
| SECRET_KEY 하드코딩 fallback | 환경변수 미설정 시 기동 실패로 변경 | `app.py` `SECRET_KEY` 블록 |
| 세션 쿠키 플래그 | `SESSION_COOKIE_SECURE/HTTPONLY/SAMESITE=Lax` 설정 | `app.py` app.config |
| 보안 헤더 부재 | CSP, HSTS, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` 적용 | `security_headers()` |
| HTTPS 미강제 | `X-Forwarded-Proto: http` 요청을 301로 HTTPS 리다이렉트 | `force_https()` |
| 로그인 실패 처리 | 실패 시 이메일·IP 경고 로그 기록, rate limit 저장소를 `RATELIMIT_STORAGE_URI`로 분리 | `app.py` 로그인 라우트 |
| 잔존 CNAME | 재지정으로 해소 — 메일에 변경 사유로 기재 | 아래 메일 초안 |

> **배포 전 필수**: Render 환경변수에 `SECRET_KEY`를 반드시 추가해야 한다. 없으면 기동 실패한다.
> 로컬 개발은 `LOCAL_DEV=1`을 설정하면 HTTPS 강제와 Secure 쿠키가 해제된다.

### 개인정보 관련 보완 — 처리 완료

| 항목 | 조치 |
|---|---|
| 문의 폼에 수집·이용 동의 없음 | 동의 체크박스 추가(`templates/contact.html`), 미동의 시 서버에서 저장 차단 |
| 홈페이지 개인정보처리방침 없음 | `/privacy` 페이지 신설(`templates/privacy.html`), footer에 링크 추가 |

### 개인정보처리시스템 점검표에서 별도로 답해야 할 것

- 저장 위치: Supabase(외부 SaaS) — **리전 확인 필요**. 방침에는 미국으로 기재해 두었으니
  서울(`ap-northeast-2`)이면 `templates/privacy.html` 4항을 수정한다. 웹 서버(Render)는
  `gcp-us-west1` 확인됨.
- 처리하는 개인정보: 연구자 계정(이메일 + 해시된 비밀번호), 문의 폼(`contact_messages`:
  이름·이메일·내용). 연구 참여자 데이터는 가명처리.
- 보관 기간: 방침에 문의 1년, 접속·감사 기록 1년으로 명시했다. 실제 운영과 다르면 조정한다.
- 앱(Mind Mate)은 Google Apps Script → Google Sheets 전송 구조 — 홈페이지와 분리된
  처리 경로임을 명시.
